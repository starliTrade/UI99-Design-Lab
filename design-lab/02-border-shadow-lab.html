UI99 / DESIGN LAB / SPRINT 02

Nested Composition Decision Engine

This experiment evaluates a real component tree. Each node receives its own decision from the surface of its actual parent, local fill separation, nesting depth, role, size, elevation and interaction state. A “Card” is not automatically given a border.

● EXPERIMENTAL · NOT LOCKED
01

Composition inputs

Change the hierarchy and watch local decisions change. The engine does not use one global border rule.

02

Engine output

Four independent measurements are shown, but the important output is the local decision for every node.

03

Real nested component

One component tree: Canvas → Card → Panel → Control, plus a sibling panel and a floating surface. No decorative borders are pre-applied to the component shells.

04

Per-node derivation

The same mathematical engine runs independently at each parent/child boundary.

05

Model under test

The hypothesis is that separation mechanisms should communicate missing information, not decorate semantic component names.

Local separation
Separation(node) = distance(surface(node), surface(parent(node)))

Edge need
EdgeNeed = RoleEdge × Size × EdgeExposure × (1 − FillClarity) × InteractionBoost × DepthDamping

Depth need
DepthNeed = RoleDepth × ElevationDemand × (1 − FillClarity) × DepthExposure

Decision
Surface Only → Border Only → Shadow Only → Border + Shadow
chosen only when the corresponding mechanism adds new structural information.

No threshold here is a locked UI99 token. This sprint is testing the architecture of local decisions and nested coherence.
06

Evidence gate

Nothing moves into the production token engine until the tree survives color, role, nesting and perceptual tests.

MATHEMATICAL

Deterministic, bounded and locally evaluated.

PERCEPTUAL

Hierarchy reads without border noise.

NESTING

Parent/child depth does not accumulate decoration blindly.

IMPLEMENTATION

Pure functions and regression cases can be extracted.
