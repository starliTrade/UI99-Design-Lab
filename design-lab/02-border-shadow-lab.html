Border × Shadow Decision Engine

A controlled experiment for deciding whether a component needs no separation, a border, a shadow, or both. The engine derives separation from the actual context/surface luminance relationship, then adjusts for component role and requested depth. Thresholds are experimental and intentionally visible.

EXPERIMENTAL · NOT LOCKED
01

Controlled variables

The foundation is B: Canvas → Surface. Change values to test whether the decision survives beyond one color pair.

02

Decision engine

Border and shadow are separate channels. Border answers “is the edge clear?” Shadow answers “is there depth?”. The engine avoids using both unless the current separation needs both signals.

04

Derived parameters

These are outputs of the current experimental model, not production tokens.

05

Current model

Keep the equations explicit so a failed visual test can tell us exactly which assumption needs revision.

ΔL = |Lsurface − Lcontext|
Separation = ΔL / (Lsurface + Lcontext + ε)

BorderNeed = edgeNeed × roleFactor × (1 − Separation) × (1 − 0.55 × Separation)
ShadowNeed = depthNeed × elevationFactor × (1 − Separation × depthSuppression)

BorderStrength = clamp(BorderNeed, 0, 1)
Border activates only above the experimental edge threshold
ShadowStrength = clamp(ShadowNeed, 0, 1)

Interpretation: when fill already separates strongly, additional decoration is suppressed. As depth increases, shadow becomes more useful; border remains an edge-clarity mechanism rather than an elevation mechanism.
06

Evidence gate

No threshold becomes a locked UI99 token until it survives multiple contexts and visual review.
